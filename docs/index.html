Lewi 1 / Documentation

Reasoning. Memory. Verification. Growth.

A living research architecture for a continually improving agent.

Lewi 1 separates general cognitive capability from experience accumulated at runtime. The current implementation combines a post-trained model with an executable agent loop, external memory, tool execution, verification-oriented control rules, and persistent interaction traces.

01 / Overview

From a model to a system that can learn from experience

MODEL

General cognition

The base model supplies language understanding, abstraction, coding, and general reasoning capability. We do not require every experience to be baked back into its parameters.

RUNTIME

Agentic execution

The runtime turns the model into an executable loop: reason, act, observe, update state, verify, recover, and continue until the goal is met or the step budget is reached.

EXPERIENCE

External memory

Experience is stored outside the weights as structured memory and interaction traces, keeping long-term state distinct from the active neural model.

One controller, multiple control points

The research architecture treats planning, retrieval, verification, and memory decisions as structured control points around the same reasoning policy rather than as disconnected “brains”.

  • Difficulty and uncertainty estimate before expensive reasoning.
  • Small hypothesis sets when ambiguity or failure cost justifies branching.
  • Hard verification when a deterministic checker, compiler, test, schema, or evidence check exists.
  • Re-planning when observations invalidate earlier assumptions.
  • Explicit stopping when the success criterion is satisfied or further information has low value.

03 / Reasoning

Reasoning should be adaptive, not ceremonial

Adaptive compute

Use the smallest sufficient strategy

Trivial deterministic questions should not pay for a deep agent loop. Hard or uncertain tasks can escalate compute, branching, and verification as warranted.

Hypothesis management

Keep alternatives alive when evidence is weak

When several causes remain plausible, preserve a small ranked hypothesis set and seek discriminating evidence instead of committing to the first plausible story.

Verification

Falsify before declaring success

Model confidence is not a hard verifier. Where possible, use tests, compilers, exact checks, schemas, source evidence, or environment state to validate the result.

04 / Agent loop

Reason → act → observe → update

01 / PLAN

Parse the user goal, constraints, dependencies, risk, and success criterion.

02 / SEARCH

Use memory as experience and retrieve only when it can inform the current decision.

03 / ACT

Choose the smallest useful tool action: code execution, file I/O, memory search, or memory write.

04 / OBSERVE

Read the actual result. A successful tool call with empty or partial payload is still incomplete state.

05 / RECOVER

When the action fails, change the strategy, scope, source, or assumptions instead of blindly repeating it.

06 / VERIFY

Require evidence that matches the success criterion before the system claims completion.

07 / LEARN

Store only durable, reusable, evidence-backed experience with explicit applicability boundaries.

05 / Memory

Memory is experience, not truth

EPISODIC

What happened

Interaction traces capture concrete episodes, observations, failures, and outcomes without turning every incident into a general rule.

PROCEDURAL

What tends to work

Repeated, verified episodes can become scoped procedures or lessons with conditions, exclusions, and evidence.

FACT / HYPOTHESIS

What we currently believe

Stable facts and unresolved hypotheses remain distinct. Version and time context matter, so updates should preserve historical state rather than erase it.

Write gates prevent memory poisoning

  • Do not convert a single incident into a global rule without supporting evidence.
  • Store applicability and exclusions, not just a semantic summary.
  • Keep user preferences scoped to the user; do not leak them into global knowledge.
  • When evidence changes, prefer version-aware update or supersession over silent overwrite.

06 / Retrieval

Similarity is a starting point, not the decision rule

Retrieval should be context-sensitive. A memory can be semantically close and still be wrong for the current version, environment, user, or failure signature.

  • Re-rank by task context, scope, recency, evidence quality, and environment match.
  • Demote superseded memories unless they are needed as historical context.
  • Group duplicates and shared-source repetitions so repetition does not masquerade as corroboration.
  • Use memory to seed hypotheses, then verify against fresh external or deterministic evidence when needed.

07 / Learning

A staged path from conditioning to continual improvement

01

SFT

Teach the control policy: situation state, adaptive compute, verification, recovery, memory scope, and explicit tool actions.

02

Rejection sampling

Generate multiple trajectories and keep those that demonstrate good strategy selection and verified outcomes, not merely longer reasoning.

03

Verifier-driven RL

Where objective checks exist, reward successful outcomes using tests, compilers, exact answer checks, schemas, or evidence consistency.

04

Memory utility learning

Train memory writes against delayed usefulness: write → future retrieval → future task outcome, while tracking negative transfer.

05

Agentic trajectory RL

Train multi-step trajectories for planning, tool choice, observation handling, recovery, evidence quality, and task completion.

09 / Research basis

The architecture is informed by modern reasoning, agent, search, and memory research

DeepSeek-R1

Verifier-driven reinforcement learning provides a basis for rewarding useful reasoning behaviors such as verification and strategy adaptation on tasks with checkable outcomes.

 Search-R1

Search can be part of the learned reasoning loop rather than a separate lookup stage, supporting the design of retrieval-aware reasoning control.

 Deep Research Agents

Long-horizon research requires strategic querying, evidence assembly, cross-validation, and decisions about when evidence is sufficient.

 Verification survey

Test-time scaling is more reliable when generation is paired with explicit verification rather than treated as a single unconditional generation step.
Memory research

The project research synthesis also draws from H-MEM, LightMem, AgeMem, and MemPO to motivate hierarchical retrieval, lightweight memory controllers, consolidation, and learned memory management.

10 / Implementation

What the repository can actually do today

CODE

Code execution

Executes Python inside the workspace with a 30-second timeout and returns stdout, stderr, and exit status for verification.

FILES

External state

Read/write operations are constrained to the project workspace so the agent can maintain task state without treating the transcript as its only state store.

MEMORY

Durable lessons

Structured memories are append-only JSONL records with type, scope, applicability, exclusions, evidence, and confidence fields.

11 / Boundaries

Where the current system stops

Not AGI. The project is an experiment in an architecture for general-purpose, continually improving agents. A working tool loop and external memory do not by themselves establish general intelligence.

Memory retrieval is still primitive. The current runtime performs lightweight lexical scoring over stored fields; the research direction calls for contextual and hierarchical retrieval.

Continual learning is not automatic yet. Interaction logs are recorded as raw material for future learning passes; they are not automatically distilled back into model weights.

Evaluation is not complete. The held-out set is designed to test control behavior, but the repository does not currently publish a validated score for it.
